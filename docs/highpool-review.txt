Highpool manual review

Review maps loads public/review/highpool/manifest.json in production and development.
All 500 candidates are separate pool/scene identities, not rotation/public map IDs.
Earlier review selections remain available under the collapsed earlier-maps section.

Choose a candidate, tag Keep / export, place team 1 and team 2 by clicking the
terrain, and drag either numbered marker to adjust it. Notes and decisions save
in browser localStorage. Export kept CSV refuses incomplete kept maps. Unkept
maps are never exported. Team 1 corresponds to entry 0; team 2 to entry 32.
Measurement spots show horizontal XY distances from both spawns. They are
session-only, clear when switching maps, and are excluded from storage and CSV.

The interactive terrain is rendered from compacted engine samples, using actual
bounds with Y upward and bilinear elevation interpolation. The source PNG has
plot margins, so it is linked separately instead of used for coordinate picking.
Z is approximate (boundary samples have a 1 metre inset). Validate ground height
in engine before building final explicit-entry maps. The original SCO/TXT pairs
remain immutable, with their engine auto-entry flags intact.

CSV matches the archive's kept_maps.csv schema. Its asset paths and hashes refer
to the original review package, including height_data_file. Deployment stores
lossless compact height grids rather than the original verbose sample JSON.
Keep the source ZIP for the downstream map-building workflow.

Reimport (from repository root):
  python3 scripts/import-review-pool.py /path/to/highpool_review.zip
Validate:
  npm run check:review
  node --test tests/review-pool.test.js
  npm run build
The project specifies Node 24; Node 20 cannot run the installed jsdom/undici tests.
The production prebuild checks every candidate's required assets and checksums.
public/review/highpool must be included in the deployed checkout. Vite copies it
to dist/review/highpool; no Windows paths are used at runtime.

Interactive elevation display:
The renderer and vertical legend both use the manifest's fixed colour_scale
(0.048–123.681 metres for this batch), with the rotation plots' Matplotlib
terrain palette. Individual map minima/maxima never rescale the colours.
The frame includes X/Y metre axes, 100-metre grid lines and map identity.
The caption reports each map's measured minimum, maximum, relief and bounds.
The plot canvas retains its coordinate mapping; axes and legend sit outside it.

Point placement and dragging:
The canvas starts in neutral mode. Each Place team / Measure from spawns button
arms a single placement, then switches off after that click. Click an active
button again or press Escape to cancel placement. In neutral mode, empty-map
clicks do nothing; drag any existing spawn or measurement point to adjust it.
Existing handles take priority over an armed placement tool. Measurement guides
remain session-only and never enter browser storage or CSV exports.

3D terrain preview:
Use 3D terrain in Review maps to orbit, zoom, pan, choose aerial/opposite/overhead
cameras, show 2-metre contours, or exaggerate heights 2x/4x (1x is the default).
The same shared elevation range and terrain palette apply; preview lighting
changes apparent brightness. Numbered markers show only placed spawns, including
partially reviewed maps. Return to 2D to edit spawns and measurements. Switching
maps rebuilds the mesh from that candidate's existing grid. Leaving 3D or the
Review tab releases the graphics resources. WebGL failures leave 2D available.
No additional terrain downloads are needed beyond the existing height grids;
this preview contains measured ground, not trees or scene objects.
